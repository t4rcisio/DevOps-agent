Responding to approval requests

Edit online

If a deployment requires approval, create an approval process that generates an approval request. Approvers respond to the requests on the Work Items tab where they approve or deny requests. You can also allow approvers to respond to requests through email.

Until a job is approved, an unscheduled deployment remains idle. If time elapses on a scheduled job that needs approval, the job fails. This control allows the approver to verify the deployment details, and choose the time that it is deployed. Notifications are sent to users who are eligible to complete an approval step if the system is configured with an email server and the user has an email address set.

You can review your approval requests in the Works Items tab. This page displays the name of the process, when the request was submitted, who requested the process, and the snapshot or version used. You can also view details of the environment or resource by clicking the link in the Environment/Resource column. They can view the details of the target by clicking the link in the target column. Or they can view details on the request by selecting the View Request in the Actions column. The Actions column is also where the approver can respond to the request.

Beginning with version 7.1.1, you can also respond to approval requests through email. An email request provides a link where you can approve or deny the request. The linked-URL does not require a logon to the Web application. If a request requires several approvals, each approver receives a unique link where they can respond.

An open request displays the status as Pending Response. To respond to a request, click actions, and then Respond. The approver has the option of leaving a comment. If a request is rejected, the process does not run. If approved, the process begins.
