Cleaning up targets

Edit online

If you have storage issues and feel that you need to cleanup some unnecessary stored data, you can use cleanup settings to cleanup your database and file system storage.

You can define the cleanup settings for the deployment history, generic process history, snapshots, and component versions from the System Settings page. Before you define the cleanup settings, know how these cleanup settings affect your database and file system:

  • Deployment History Cleanup: This setting primarily deletes database files or entries. However, it also removes log files from the file system.
  • Generic Process History Cleanup and Snapshot Cleanup: Both of these settings exclusively delete database files.
  • Component Version Cleanup: This setting mainly cleans up the file system, but it also deletes some associated database files.
  • Creating a rotating audit log file
    You can create rotating audit log file at a regular interval, such as every day.
  • Cleaning up deployment history files
    You can clean up deployment history files to reduce database and file system storage that IBM DevOps Deploy (Deploy) uses.
  • Cleaning up component versions
    You can configure the server to reduce the number of component versions by archiving them. You can specify artifacts cleanup settings from the System Settings, or cleanup settings for individual components, and environments.
  • Cleaning up snapshots
    You can configure the server to reduce the number of snapshots by deleting old snapshots. You can specify global cleanup settings and cleanup settings for specific environments.
  • Cleaning up generic process history files
    You can clean up generic process history files that are generated when you run the process manually.
  • Configuring bulk cleanup settings
    On the Cleanup Configuration page, you can edit the cleanup settings of multiple components and environments at once.
